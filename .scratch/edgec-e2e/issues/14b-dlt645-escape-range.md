# 14b `dlt645._escape` 对 ≥0xCD 的字节抛难懂 ValueError(而 `_MAX_DATA` 允许 0xFF)

Status: ready-for-agent
来源:clawpatch low 项。

## 线索

`_MAX_DATA` 声称支持到 `0xFF`,但 `_escape` 对 `>= 0xCD` 的字节抛 `ValueError`,消息与本意无关。后果:**合法的数据值在编码期炸**,而且错误指向"值不合法",实际是转义实现不全。

## 要求

1. **先复现**:构造含 `0xCD`、`0xE0`、`0xFF` 的读数 → 贴异常原文与调用栈
2. 查 DL/T645 的转义规则(0x33 加/减、需要避开的字节集合),**按标准实现**,不许"遇到就抛"
3. 守卫:边界字节(`0xCC`/`0xCD`/`0xFF`)编码后再解码**round-trip 相等**;非法长度仍报错
4. 若标准确实不允许这些值,则把 `_MAX_DATA` 收窄到真实范围,并让错误消息说明**是范围错不是转义错**

## 边界

不许改证据格式;不许为了让测试过而放宽 `_MAX_DATA` 而不写清依据。
