# 46 `read(key)` 每次读整张点表(Must fix)

Status: resolved
Type: task
Blocked by: None

**What to build:** 单读一个读数键,不应该付出整张点表的往返代价。

## 现状

```python
# drivers/point_table_driver.py:74
return self.read_all().readings[key]
```

全仓 **52 处** `.read("...")` 调用。对 `vendor_ascii` 型号(逆变器/电池/台架,3 点)每次单读 = 3 次收发;20 点表就是 20 次。20ms 往返下,读 3 个量 = 180ms 而不是 60ms。

`read_all()` 本身必须保留 —— 判据要一次看全所有量才能判合格。问题是**单读也走了它**。

## 期望(二选一,取小的)

- (a) 一次读数周期内缓存:同一轮里第二次 `read(key)` 复用上次 `read_all()` 的结果,直到下一次写/显式刷新失效
- (b) `read_one(key)`:只读那一个点、只 decode 那一个量,不进 history、不判据 —— 明确"单读不带判据结论"

推荐 **(b)**:语义清楚,不会因为缓存让人误以为读到了新值。但若 `setting_cases` 的"写→读回→判等"依赖 history,要一并核对。

## 验收

- [x] 单读 1 个量 → 只有 1 次收发(用例断言帧数,不是断言耗时)
- [x] 3 点表连续 `read` 三个量 → 3 次收发(现状 9 次)
- [x] `read_all()` 仍是一次读全表、仍写 history、仍出判据结论(行为不变)
- [x] 若选 (a):缓存必须在"下一次写"或"设备重连"时失效,有对应用例
- [x] 基线不回归(609 passed / 7 skipped)
