# 40 进程内模拟器不会写多寄存器:驱动与 mock 都会,mode: simulator 下同一条写会失败

Status: resolved
Type: task
Blocked by: None

**要修什么:** 写路径现在有三方,能力不一致:

| | 0x06 单寄存器 | 0x10 多寄存器 |
|---|---|---|
| 驱动(`39`) | ✅ | ✅ |
| 独立 mock 从站(`38`) | ✅ | ✅ |
| **进程内模拟器** | ✅ | ❌ 落进 `parse_read_request` 的"不支持的功能码" |

后果:任何 `writable` 且 `length > 2` 的点(BCD 时钟 6 字节、float32 4 字节、密码 3 字节)在 `mode: simulator`(出厂清单的默认模式)下写会失败,报的还是"不支持的功能码" —— 看起来像驱动 bug,实际是模拟器缺一半。

现在没暴露只是因为出厂清单里唯一的可写点 `有功计量模式` 是 2 字节。

## 期望

1. `SimulatedModbusSlave` 支持 0x10:解析起始地址/寄存器数/数据 → 写进寄存器内存 → 回显起始地址 + 寄存器数(8 字节);异常码按 Modbus 规范(地址不存在 0x02、数量非法 0x03),与 mock 从站一致。
2. **一份"两从站行为一致"的对照用例**:同一组操作(0x06 写 / 0x10 写 / 写不存在地址 / 数量非法)在进程内模拟器与独立 mock 上产生**相同的应答字节**。这是防"两边慢慢漂开"的唯一办法 —— 现在它们已经是两套实现。
3. 证据:`mode: simulator` 下的多寄存器写,回读值与写入值一致。

## 不做

- 不改驱动侧选 0x06/0x10 的逻辑
- 不给模拟器加写之外的扩展(比如 0x0F 线圈)

## 验收

- [x] 进程内模拟器支持 0x10,应答与 mock 逐字节相同(贴两边的帧)
- [x] 异常码 02/03 两边一致
- [x] 一条 `length > 2` 的可写点,在 `mode: simulator` 下写→回读闭环通过(贴)
- [x] 对照用例覆盖四种操作,两边字节比对
- [x] 全量套件全绿
