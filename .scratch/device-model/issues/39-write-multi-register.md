# 39 写多寄存器(0x10)+ 多字节写入编码:527 条条款被它挡着

Status: resolved
Type: task
Blocked by: 无 —— 但它挡着 527 条设置类条款的真正迁移

**要做什么:** 现在 `PointTableDriver.write()` 只支持 **单寄存器(0x06)+ 数值**。上游设置类条款要写的东西大半不是这种:

| 要写的 | 形态 | 现在 |
|---|---|---|
| 密码 `"120000"` / 表地址 | BCD 字符串,3–6 字节 | ❌ `value` 必须是数值,直接拒绝 |
| 时钟 `YYMMDDhhmmss` | BCD,6 字节 | ❌ 同上 |
| 有功计量模式 `"1601"` | 单寄存器数值 | ✅ 已支持 |
| 4 字节整 / 浮点参数 | 跨 2 个寄存器 | ❌ `writable` 的点只按单寄存器写 |

设置类条款表(`35`)里 `value` 现在是数值限制,**这条不解决,527 条里能落的只有一小部分。**

## 期望

1. **0x10 写多个寄存器**:`build_write_multiple_request(slave, address, registers)` + 对应应答解析(0x10 的正常应答是 5 字节:从站 / 功能码 / 起始地址 / 寄存器数,没有数据)。
2. **多字节编码**:写入时按点表声明的 `encoding`(uint / int / bcd / float32)、`length`、`byteorder`、`word_order` **反算成寄存器序列** —— 必须与读路径的解码互为逆运算(读出来的值写回去,字节一致)。
3. **`writable` 允许 `length > 2`** 的点:按长度自动选 0x06(两字节)还是 0x10(更长)。
4. **BCD 字符串可以写**:`value: "120000"` 写 3 字节 BCD;字符串形式与 BCD 编码的对应关系要写清(是否补前导零、是否允许非数字)。
5. 写后**仍然立刻回读一次**(既有语义),回读用同一条读路径,`verified` 语义不变。

## 硬要求

- **读写必须互逆**:有一条用例专门锁"读出来的值原样写回去,寄存器字节完全一致"(往返不动点)。
- **越界不许截断**:`value` 超出该点能表示的范围(如 2 字节写 70000)→ 报错并说明范围,不许截断成另一个看着合理的值。
- **`0x10` 与 `0x06` 的选择由长度决定,不由用例决定** —— 用例只说"写这个点的这个值"。
- 单寄存器写(0x06)的既有行为与帧**一字不变**(现有用例全绿)。
- `35` 的 `setting_cases` 里 `value 必须是数值` 这条限制要放开到"与点表 encoding 相容",并保留"不相容就装配期报错"。

## 不做

- 不做写多个点(一次写多个不同地址)
- 不做写后的重试策略
- 不改读路径

- [x] BCD 字符串写入(密码 / 时钟形态):帧正确、回读一致
