# 58 DL/T 645 写路径编不了 String 类 DI:表地址 / 通信速率 / 走字条款都卡在这

Status: blocked
Type: task
Blocked by: None —— 这是 57 得出的"下一道门"

**要修什么:** 57 给 `dlt645_meter` 补了时钟日期/时间两个可写点(DI + BCD 有出处),但**表地址 `04000401` / 红外波特率 `04000701-702` / 通信口速率 `04000703-705` 补不了** —— 不是缺 DI,是写路径里**没有 String 类编码**:

- 上游图例 `#String` 只给"定长字符串",**没给字节布局**(是否 ASCII、是否补零、结束符)
- `src/testplatform/protocol/values.py` 的 `ENCODERS` / `DECODERS` 里**没有 string/ascii 写入方向**

所以即使把 DI 填进点表,写下去也编不出字节。

## 两件事,分开做

**(a) 代码:补 `string` 编码的写方向**
- `ENCODERS` 加 `string`(定长、ASCII、右补 0x00 或空格 —— **布局必须来自手册,不许猜**)
- 长度不符要拒收(短了补、长了报错),不许截断
- 读回方向要与写方向互逆(和 BCD/uint 同一套"往返不动点"用例)

**(b) 数据:特征字取值表**
- `04000701`/`04000702`/`04000703-705` 的**取值表**(波特率 ↔ 特征字整数)是外部输入
- 拿到之前**不加这些点**;拿到了加到 `configs/import/writes.yaml`

## 不做

- 不猜 String 的字节布局(ASCII? BCD? 补零还是补空格?结束符?)——**猜错的表现是"写进去了但设备拒收",或更糟:接受了一个错误的值**
- 不加 `有功计量模式` / `通信模式` 的点(57 实测 `writes.yaml` 里没有它们的 DI)

## 验收

- [ ] `string` 编码写入:给定点表项与值,拼出的字节**有出处**(图例/手册页码),并有往返不动点用例
- [ ] 长度不符:短 → 补齐;长 → 报错(不截断)
- [ ] 若 (a) 完成但 (b) 未到:表地址/速率**仍不加点**,报表里明确"缺特征字取值表"
- [ ] 全量与规模清单差值可解释(基线 702/7 · 709 · 1806/109)
