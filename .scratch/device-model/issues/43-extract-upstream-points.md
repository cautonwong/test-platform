**两条必须纠正的理解**:

1. **OBIS ≠ DL/T645 DI。** 上游给的是 DLMS 逻辑名(`0-0:96.2.241.255`,类/OBIS/属性三段),我们 `dlt645` 型号点表里写的是 4 字节数据标识(`"00010000"`)。这是两套命名体系,**不是查表照抄,是一张要按标准建立的映射**,而且不是 1:1(有些量只在一边有)。
2. **`通信模式` / `表地址` 这类名字在上游客户端根本不存在** —— 它们若存在,也在服务端的 MAL 定义(22 个 dll 之一)里,或者压根由表厂协议文档给。**本票不可能"从上游填出这 5 个参数的地址"。**

## 提什么(四类,各带出处行号)

### 1. 接线方式枚举 → 整数

上游用 `Ctype` 表示接线方式,并从它推相数:

```
E:/workspace/cmake/power/autotest-10544/tests/param.py:27    Ctype = 9
tests/param.py:69    CalPhaseNum = (Ctype==5)*3+(Ctype==9)*1+(Ctype==0)*2+(Ctype==10)*2+...
```

出现过的取值至少:`0 / 5 / 9 / 10 / 51 / 52 / 53 / 54 / 91`。要产出「中文接线方式名 ↔ Ctype 整数 ↔ 相数」三列。中文名从 xlsx 的 `接线方式="与表型一致"` 这类取值与上游配置里对。

### 2. 5 个可写参数的地址与编码

`13通信` 报表里的映射缺口:通信模式、红外通信波特率、RS485通信波特率、时钟、表地址。

查这几处(按优先级):

- `common/obisDict.py` —— 形如 `'接线方式:value':('1', '0-0:96.2.241.255', '2', 'unsigned')`,四元组是(某类编号, OBIS 逻辑名, 长度, 编码)
- `common/_meterObisDict.py` —— 形如 `'1#1.0.132.128.5.255#1'`
- `common/malDict.py`、`common/delSetMal.py` —— 名字里带 Mal 的,通常是"管理访问层"的**写**参数表
- `common/p645dict.py` —— DL/T645 的 DI 表

**产出**:参数名 → OBIS/DI + 长度 + 编码 + 出处行号。

### 3. 台架 14 量的单位/量程/倍率

`common/oper_object/runtime.py` 的 `runWord(...)` 参数(**读 docstring**):`fUe / fIe / fHz / fRangeUa..c / fRangeIa..c / fAngleUaIa.. / fPercent / MeterConst`。要产出:每个量的物理单位、是否是百分比(如 `fRangeIa` 是额定电流的百分比)、是否有正负、整数还是浮点。

### 4. 单位与倍率的书面约定

`tests/param.py` 里大量 `1.2Un`、`Un`、`Hz` 之类的写法 —— 提取"条款里怎么写设定值 → 实际数值怎么算"的规则(例如 `Ua=Un` 表示 100% 额定电压)。

## 硬约束

1. **每条都要带 `文件:行号` 出处**。查不到的**留 TODO**,不许用"看起来合理"的值填 —— 编出来的地址是最坏的一种假绿(和 42 里地址占位同一条理由)。
2. **区分两件事**:上游走的是 **DLMS OBIS 逻辑名**,能直接用于我们的 `dlt645` 型号(DI 是 4 字节),**但不能当 Modbus 寄存器地址**。Modbus 型号(如 `dtsd1352_modbus`)仍需要厂家寄存器表 —— 这一点要在产物里写明,别让人以为填上 OBIS 就能跑 Modbus。
3. 只读上游,不复制代码进来;产物落成本仓的 yaml + 一份 `docs/upstreams.md` 的取材记录。
