# 42 台架型号能力缺口:条款前置要高三相台架 11 个量,我们只有 2 个

Status: resolved
Type: task
Blocked by: None(形状可先做);地址部分等外部输入

**What to build:** xlsx 1,921 条条款的前置几乎每条都是一整块三相台架设定,实测有 **149,992 行参数、33 个量名**,核心 11 个是 `Ua/Ub/Uc/Ia/Ib/Ic/θa/θb/θc/QUaUb/QUaUc/Fre` 加 `接线方式`。而我们的台架型号 `grid_simulator_3ph` **只有 `电压` 和 `频率` 两个量**。

`41-bench-prefix-field-for-setting-cases.md` 解决的是"前置怎么写进清单";本票解决的是**写进去以后没有东西能接**。

## 实测

全表 `操作类型 == 调整台体` 的对象参数行按量名统计(前 13 个几乎每条条款都有):

| 量名 | 出现次数 | 我们的台架有吗 |
|---|---|---|
| `Ib` / `Ia` / `Ic` | 11,528 / 11,507 / 11,484 | ❌ |
| `Ua` / `Ub` / `Uc` | 11,514 / 11,502 / 11,501 | 部分(只有单一「电压」) |
| `θa` / `θb` / `θc`(压流角) | 11,505 ×3 | ❌ |
| `QUaUb` / `QUaUc`(相间角) | 11,507 ×2 | ❌ |
| `Fre` | 11,507 | ✅(「频率」) |
| `接线方式` | 11,496 | ❌ |
| `MeterConst`(表常数) | 84 | ❌ |
| 谐波(次数 / 含有量 / 相角) | 48 ×4 | ❌ |
| `In(零线)` / `掉电` 等 | 20 / 23 | ❌ |

`grid_simulator_3ph` 现状:`capabilities: [电压, 频率]`,`point_table: {电压, 频率}`。

## 关键区分:形状 vs 地址

这两件事的阻塞性质完全不同,**不要一起等**:

| | 形状(可以先做) | 地址(必须等外部输入) |
|---|---|---|
| 内容 | 型号声明哪些量、`bench:` 字段怎么引用、驱动怎么下发三相设定 | 每个量在台架上的寄存器地址 / 编码 / 倍率 |
| 谁能做 | 代码 | 真实台架手册或实测 |
| 现在能不能动 | **能** | 不能 |

所以本票做**形状**,地址先用占位并在装配期报"缺少真实地址,不可上真机":

```yaml
models:
  grid_simulator_3ph:
    type: grid_simulator
    protocol: vendor_ascii          # 或 modbus_rtu,取决于真台架
    capabilities: [三相电压, 三相电流, 压流角, 相间角, 频率, 接线方式, 表常数]
    point_table:
      电压:   {address: ..., length: 2, encoding: uint, scale: 0.1, unit: V, writable: true}
      电流:   {address: ..., writable: true}
      ...                             # 地址留空 / 标 TODO,装配期拒绝上真机
```

## 期望

1. **型号能力扩到 13 个核心量**(三相电压/电流分开声明,不要合成一个「电压」—— 条款里 `Ua` 和 `Ub` 是独立的)
2. **`接线方式` 不是模拟量是枚举**(3P4W / 3P3W / 单相 …),点表要有枚举编码的位置;`MeterConst` 是整数参数
3. **装配期守卫**:`mode: real` 且某个量的地址还是占位 → 报错,消息说明"该量缺真实寄存器定义,不能上真机";`mode: simulator` 允许跑
4. **模拟台架**能接受三相设定并按设定回读(现在是单相电压/频率,三相要扩)

## 不做

- 不编造寄存器地址(编出来的地址就是最坏的一种假绿)
- 不为每个条款单独定义一个台架量名(33 个里前 13 个是核心,其余按需)
- 不把台架量和被测设备的量混在一个点表里
