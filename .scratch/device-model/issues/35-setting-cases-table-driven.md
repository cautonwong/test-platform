# 31 527 条设置类条款没有对应的写法:不定义"表格驱动",就会有人写 527 个场景函数

Status: resolved
Type: task
Blocked by: 26(写原语)、27(`equals`)

**What to build:** 实测上游 659 条条款里 **527 条(80%)是"写 N 个参数 → 读回 → 判相等"**,`universalSet` 调用次数的中位数是 6,参数值高度重复(`"1101"` 出现 1624 次、`"F001"` 942 次、`"1600"` 949 次)。这类条款**不该写进 `tests_scenario/`**:没有因果链,没有跨设备联动,写成场景函数就是把上游 350 行/条的文件换个外壳。

平台现在没有承载它们的形状 —— 不定义,迁移时一定会有人写 527 个场景函数。

## 判据(可验收的量)

> **迁移后一条条款对应的 Python 行数必须显著小于上游文件的行数。没降,说明写法错了。**

| | 上游 | 目标 |
|---|---|---|
| 一条设置类条款 | 一个 350 行的 `test_M_*.py` | yaml 里 3–6 行 + 0 行 Python |
| 527 条总量 | 231,018 行里的绝大部分 | 1 个函数(约 20 行)+ 约 3000 行 yaml 条目 |
| 期望值(阈值) | 散在调用参数与函数默认值 | 一行一条,改一处生效 |
| 加一条新条款 | 新建文件 | 加几行 yaml |

## 期望的形状

清单新增一段 `setting_cases`(按条款编号分组),用例侧一个函数:

```yaml
setting_cases:
  M_00_00_01_000002_01:
    clause: "DL/T 645 4.5.2"
    steps:
      - {write: 进入/退出工厂模式, value: "F001",  expect: "F001"}
      - {write: 密码,             value: "120000", expect: "120000"}
      - {write: 密码,             value: "1601",   expect: "1601"}
      - {write: 有功计量模式,      value: "1601",   expect: "1601"}
```

```python
@pytest.mark.parametrize("case_id", setting_case_ids())    # 从清单读,不是手写列表
@case(id=..., clause=..., tags=["一致性", "设置"])          # ← 见下方「身份」一节
def test_setting_roundtrip(meter, case_id):
    """写完立刻读回:值一致才算通过,期望值全在清单里。"""
    for entry in setting_cases(case_id):
        meter.write(entry["write"], entry["value"])
        assert meter.read(entry["write"]) == entry["expect"]
```

**`@case` 身份问题必须先解决**:一个函数参数化成 527 个节点,`24-case-id-uniqueness-under-parametrization.md` 已定规则 —— `@case.id` 表达用例身份(条款),参数表达取值。所以要么一条条款一个 `@case`(那就得 527 个函数,退化成上游),要么让 `@case.id` 从 `case_id` 参数取。

**推荐后者**:`@case` 支持"由参数给 id",例如 `case_from_param("case_id")`,收集期给每个参数节点挂上 `setting_cases` 里对应的条款编号与 clause。这样 527 条条款在证据/归因里各有自己的编号,而代码只有 1 个函数。**这一条是 24 的延伸,必须在做本票前定下来。**

## 边界

| 归本票 | 不归本票 |
|---|---|
| 单向"写 → 读回相等" | 需要判断"写被拒"的不同异常码语义(26 里定义) |
| 参数只来自清单 | 参数依赖前一步读数(那是有分支,拆条款) |
| 期望值是单个值 | 期望是区间(用判据集) |
| 单设备 | 跨设备(走字类,29 条,走场景层) |

- [x] 一个函数 + 清单驱动,跑出"N 条条款 = N 个节点",节点 id 带条款编号
