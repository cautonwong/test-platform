# 基线

以后任何改动都跟这份比,而不是每次临时跑一遍、也不是跟记忆里的数字比。

**规则:任何改动后跑下面 §这次基线 里的全套命令;数字变了解释,解释不了就修。**
没有这句话,基线只是一份历史快照 —— 它的价值在比较流程,不在数字。

### 数字的有效期

**每个数字都带 commit,不带出处的数字会被当成永远有效。**

```
规模清单   1789 passed / 109 skipped   @ ea3e35b
收集数     692                          @ ea3e35b
默认套件   685 passed / 7 skipped       @ ea3e35b
```

**闸门数字必须开工前当场量,不能用上一轮记的。** 拿旧数字卡新改动,会得到"假红" —— 而那会让人去改本来没问题的代码。

### 规模清单:串行 vs 并行(随用例数变化,不是固定倍数)

```
规模 串行            1789 passed / 109 skipped   63.9s   @ ea3e35b
规模 -n 4 loadgroup  1789 passed / 109 skipped   35.0s   @ ea3e35b   (1.82×)
```

同一 commit、同一份清单,**结果完全一致** —— 这条同时证明"并行没丢用例"(不是跑得快因为少跑了)和"总线分组在 265 台上没炸"。

**收益随用例数变化**:1543 条时是 1.25×,1789 条时 1.82×,差别来自 worker 启动开销(约 2.9 s)被摊薄。所以不要把它写成固定倍数。

**别拿这个倍数承诺真机时间**:模拟器下用例几乎瞬时,真机每条几十毫秒起步,分布完全不同。

## 口径与前提(不写清就会拿错的数字)

- **行数**:手抄清单去重后测试文件 753 → 256(−497);含新增的工厂与 `tests_support/` 后,那一轮整仓净 −151(`+733 −884`)。两个数都对,口径不同。
- **绝对值不可跨环境比**:机器上有别的进程跑飞时,全量能从 35 s 变成 50 s+(实测过一次)。比时间要同一天、同负载。
- **`--count=2` 会改节点 id**(`[meter_01-2-2]`),`--lf` 因此对不上;复现要用 `--randomly-seed` + `--count=2` 重跑。
- **零用例的一轮**是闸门不是功能:`incomplete` 才对,`clean` 说明归因在撒谎。
